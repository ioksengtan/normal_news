# 科技版每日出刊

每天台北時間 07:00 出一刊。科技版在這個時間抓一次，當天不再改，像印好的報紙。重跑同一天會覆寫該期內容，刊號不變。

這個流程不呼叫模型。摘要由助手自己寫。不要把模型金鑰放進工作流程。

報紙順序是科技．GitHub、科技．Hacker News，然後國際版。GitHub 第一則是頭條。國際版讀 `data/international.json`，目前維持空陣列，頁面顯示「今日國際版尚無新聞」。科技版這份步驟不填國際版。

## 每天執行的指令

在儲存庫根目錄：

```bash
node scripts/fetch-tech.js
```

抓取使用與國際版相同的使用者代理字串 `normal-news-bot/0.2 (+https://github.com/ioksengtan/normal_news)`。

這會寫出 `data/tech/candidates.json`。GitHub 先解析 https://github.com/trending?since=daily ，失敗或少於 10 則時改走搜尋介面（過去 7 天新建、依星數排序），並在候選檔標記備援。Hacker News 讀官方的 `topstories.json` 與 `item/{id}.json`。過去 3 期出現過的 GitHub 專案、前一期出現過的 Hacker News 討論、以及徵才貼文會自動跳過。

若備援搜尋遇到未登入的每小時次數上限，用 GitHub CLI 的權杖再抓一次。在 GitHub Actions 裡則帶工作流程內建的 `GITHUB_TOKEN`：

```bash
GITHUB_TOKEN="$(gh auth token)" node scripts/fetch-tech.js
```

接著依候選檔寫 `data/tech/summaries.json`，再入庫：

```bash
node scripts/ingest-tech.js
git add data/issues
git commit -m "issue: YYYY-MM-DD 科技版"
git push
```

把 `YYYY-MM-DD` 換成候選檔裡的 `date`。某一版抓取失敗時仍然執行入庫，該版會顯示「今日未能取得」，其他版照常出刊。

## 摘要規則

用平實、可查證的中文，只寫候選資料與原文裡已經有的事實。不要情緒用語，不要評價好壞，不要加上原文沒有的推論。每則摘要長度 150 至 300 字（內容長訂的建議值），並遵守下方「科技版摘要不使用情緒用語」條文。

- GitHub：兩到三句，依專案描述與說明文件（README）撰寫：它是什麼、做什麼、給誰用。專案名稱保留原文。
- Hacker News：中文標題另寫，原文標題保留。摘要兩到三句，摘要所連結的文章。沒有連結的「問 Hacker News」就摘要貼文本身。原文無法取得，或該網站的 robots.txt 禁止人工智慧代理程式抓取時，不抓原文，改依 Hacker News 討論整理，並在摘要中註明。

摘要檔格式：

```json
{
  "date": "2026-09-30",
  "github": {
    "owner/repo": "兩到三句中文。"
  },
  "hackernews": {
    "12345": {
      "titleZh": "中文標題",
      "summary": "兩到三句中文。"
    }
  }
}
```

`date` 必須和候選檔相同。正式出刊不要使用 `--allow-placeholders`。預覽用的占位字樣是「【占位摘要」和「【待譯」。

## 科技版摘要不使用情緒用語

以下條文取自內容長的草稿（`drafts-2026-09-30.md` 第三節），每一則科技版摘要都要遵守。原條文中 `section`、`neutral_text`、`removed_spans` 等輸出欄位是給模型管線用的；科技版摘要檔沒有這些欄位，改由撰寫摘要的助手在寫作時直接套用規則。

**（甲）長度與範圍**

1. 摘要長度 150 至 300 字，只能包含原文有的資訊。
2. 類別與優先順序：人身攻擊、未經查證推論、模糊或匿名來源、片面框架、誇大或絕對化用語、情緒用語、其他。

**（乙）一般原則**

1. 摘要不得使用科技報導中常見的情緒或炒作用語，例如「顛覆」「震撼」「強大」「驚人」「爆紅」「革命性」「史上最」「殺手級」「全面超越」「滅頂級」，以及英文的 "game-changing"、"revolutionary"，還有沒有具體依據的 "breakthrough"。處理方式見下方用語表。
2. 類別判定：
   - 最高級、絕對化的說法（例如「史上最」「全面超越」）歸為「誇大或絕對化用語」。
   - 表達情緒或誇張感受的說法（例如「震撼」「驚人」「爆紅」）歸為「情緒用語」。
   - 沒有指明是誰說的預測或影響判斷，歸為「未經查證推論」。
   - 「業界人士認為」這類沒有具名的來源，歸為「模糊或匿名來源」。
3. 如果這些用語出現在有明確發言者的直接引述中，可以保留在引號內並標明發言者，但摘要的敘述句不得沿用。

**（丙）公司說法與效能數據**

1. 效能、測試成績、市占率等說法，要寫明是誰說的，例如「某公司表示……」。只有在原文顯示這些說法來自該公司時，才能這樣寫，不得自行推定來源。
2. 保留原文的數字與測試條件（測試項目、比較對象、硬體環境、日期）。
3. 原文沒有說明測試條件或數據出處時，在摘要中寫「原文未說明測試條件」。這是本站的註記，不算增加新資訊。
4. 不得使用未經查證的最高級說法（例如「最快」「最強」「領先業界」）。只有在原文引用第三方測試並寫明條件時，才能寫成「根據某機構的測試，在某條件下……」。

**（丁）產品發表**

1. 不使用行銷形容詞（例如「旗艦級」「極致」「驚豔」「神級」）。
2. 只寫可查證的事實：產品名稱、規格、價格、上市日期、銷售地區。原文沒有的項目就不寫，不得猜測。

**（戊）對未來影響的推測**

1. 只有在指明是誰的看法時才能寫，例如「某分析師認為……」「某公司預估……」。
2. 沒有指明來源的影響判斷（例如「將改變整個產業」），歸為「未經查證推論」並刪除。

**（己）資安事件**

1. 不使用製造恐懼的用語（例如「駭人」「恐慌」「全面淪陷」「末日」）。
2. 寫明事實與影響範圍：哪個單位受影響、哪些系統、影響人數或資料筆數（並寫明數字出處）、是否已有修補程式或官方公告。
3. 攻擊者身分只有在指明來源時才能寫，例如「某公司表示，攻擊來自……」。

**（庚）股價與市場變動**

1. 不使用「暴漲」「噴出」「崩跌」「崩盤」「血洗」等用語，改用數字，例如「上漲 12.5%」「下跌 8.2%」，並寫明時間範圍與市場。
2. 股價變動的原因，只有在原文指明是誰的看法時才能寫，否則不寫因果關係。

**科技版常見炒作用語與中性處理方式（24 項）**

| 用語 | 常見類別 | 中性處理方式 |
|---|---|---|
| 顛覆、顛覆性 | 誇大或絕對化用語 | 刪除，改寫實際改變了什麼，例如「改以訂閱制收費」 |
| 革命性、劃時代 | 誇大或絕對化用語 | 刪除，改寫具體的新功能或新做法 |
| 史上最、史上首見 | 誇大或絕對化用語 | 刪除。若原文有可查證的紀錄，改寫為「某公司表示，這是該公司首款……」並保留數字 |
| 全面超越、遙遙領先 | 誇大或絕對化用語 | 改寫為有出處的比較，例如「某公司表示，在某測試中得分比某產品高 12%」 |
| 碾壓、秒殺 | 誇大或絕對化用語 | 改寫為具體數字差距並寫明出處；沒有數字就刪除 |
| 滅頂級、殺手級 | 誇大或絕對化用語 | 刪除修飾語，只保留產品或功能名稱 |
| 霸主、王者 | 誇大或絕對化用語 | 改寫為有出處的市占率數字，例如「根據某調查機構的資料，市占率為 35%」 |
| 強大 | 誇大或絕對化用語 | 改寫為具體規格，例如「採用 16 核心處理器」 |
| 神級、神器 | 誇大或絕對化用語 | 刪除，只寫產品名稱與功能 |
| 黑科技 | 誇大或絕對化用語 | 改寫為技術的具體名稱或原理，例如「固態電池」 |
| 震撼、震撼登場 | 情緒用語 | 刪除，改寫為「發表」「推出」 |
| 驚人、驚豔 | 情緒用語 | 刪除，保留原文的數字或事實 |
| 爆紅、瘋傳 | 情緒用語 | 改寫為有出處的數字，例如「某平台資料顯示，下載次數達 500萬次」；沒有數字就刪除 |
| 瘋搶、秒殺完售 | 情緒用語 | 改寫為「某公司表示，首批產品已售完」，保留數量與時間 |
| 恐慌、駭人 | 情緒用語 | 刪除，寫明影響範圍與數字 |
| 暴漲、噴出 | 情緒用語 | 改寫為「上漲 12.5%」，並寫明時間範圍與市場 |
| 崩跌、崩盤、血洗 | 情緒用語 | 改寫為「下跌 8.2%」，並寫明時間範圍與市場 |
| 將改寫產業、將取代人類 | 未經查證推論 | 有指明來源時改寫為「某分析師認為……」；沒有指明來源就刪除 |
| 業界人士認為、外界普遍看好 | 模糊或匿名來源 | 改為原文中具名的來源；原文沒有具名就刪除 |
| game-changing | 誇大或絕對化用語 | 刪除，改寫具體改變了什麼 |
| revolutionary | 誇大或絕對化用語 | 刪除，改寫具體的新功能 |
| breakthrough（沒有具體依據時） | 誇大或絕對化用語 | 改寫為「新方法」「新成果」，並保留原文的數據與出處；有同儕審查論文等依據時，可寫「研究團隊發表的成果」 |
| cutting-edge、state-of-the-art | 誇大或絕對化用語 | 刪除，改寫具體技術規格 |
